The package has useful domain modules and substantial scientific tests. Its strongest opportunities are to remove parallel orchestration paths, capture results explicitly, and retire verified leftovers. A broad rewrite is not supported by the evidence.

Top architectural recommendation

A1 · Make reference-panel preparation the execution seam

It comes first because the tested adapter and production calculation demonstrably disagree on raw-R² correction, and production repeats PLINK preparation. The existing PLINK/parquet alternatives justify a real seam. Deepening it can concentrate scientific policy and eliminate wasted work without inventing a new architecture.

Suggested sequence: resolve the three confirmed defects (A1, A3, A8) in small focused changes; then deepen A1 and centralize artifact declarations (A2). Take C1/C2/C3 cleanup in separate changes. This is a recommendation, not an approved implementation plan.

Review scope only. No package code, tests, documentation, or tracked resources were changed. Candidate selection authorizes design exploration; implementation needs an explicit selection and authorization under the requested review skill.

StrongA1

Make reference-panel preparation the execution seam

Highest architectural leverage: a reproduced R² correction mismatch, repeated genotype preparation, and tests exercising a reader that production bypasses.

Observed friction and affected paths

  • src/ldsc/ldscore_calculator.py:674 — compute_chromosome aligns through the panel, then reconstructs a parser namespace and branches on ref_panel.spec.backend at lines 682–706. It calls the PLINK/parquet kernel directly. Repository call-site search found RefPanel.build_reader() consumers in tests, not the production workflow.
  • src/ldsc/_kernel/ref_panel.py:168 — _resolve_r2_bias_from_meta resolves raw/unbiased metadata for the adapter. src/ldsc/ldscore_calculator.py:3180 passes r2_bias_mode=None; src/ldsc/_kernel/ldscore.py:1890 constructs SortedR2BlockReader directly. The raw correction is therefore skipped on this path.
  • Reproduced with two SNPs and one stored raw R²=0.5 pair at n=200: adapter pair value 0.4974747598; public chromosome LD scores [1.5, 1.5]; corrected expectation [1.4974747896, 1.4974747896]. This concerns an accepted synthetic external raw-R² panel. The package builder emits unbiased R² and is unaffected by this example.
  • src/ldsc/_kernel/ref_panel.py:383 — _load_genotype_metadata opens PLINK to derive MAF, while kernel preparation opens it again. A fixture probe counted two PlinkBEDFile constructions for one chromosome (8 source rows, 4 retained). src/ldsc/ldscore_calculator.py:688 coordinates repeated cleanup with _plink_identity_cleanup_already_logged.
  • src/ldsc/_kernel/plink_bed.py:221 opens a file and retains self._fh at line 241 without a close/context interface. The unittest run reported unclosed-file ResourceWarnings; reader lifetime belongs with prepared panel state.

Current coordination

↓
Workflow inspects backend and rebuilds Namespace
↓
Kernel reopens panel; separately supplies bias/filter state

Proposed seam

Workflow requests prepared chromosome
↓
Reference panel owns identity, filters, reader, R² policy
↓
Kernel computes from that prepared state

Proposed change and tentative seam

Deepen the existing reference-panel module around a resolved, chromosome-scoped prepared panel. Put retained metadata, physical BED indices, sample/MAF selection, sidecar binding, R² correction, and reader lifetime behind this seam. Keep the two actual adapters (PLINK and parquet). Let numerical kernels consume prepared inputs rather than rediscovering paths or reconstructing policy.

Expected leverage, locality, and testing benefit

Leverage: callers get one coherent preparation and execution path. Locality: identity, bias, filtering, and resource ownership change together. Testing: exercise the same seam used by LD-score calculation. Reduced duplicate preparation is measured; total runtime savings still need benchmarking.

Deletion test

Deleting the existing RefPanel classes wholesale would scatter useful discovery/filtering behavior. Delete the bypass and repeated preparation instead; the prepared-panel module earns its keep by hiding real backend differences.

Tests that should survive or be added

Retain PLINK/parquet golden parity, sidecar binding, row remap, common-MAF, ordering, and restriction tests. Add a public raw-R² chromosome case, one-preparation call-count assertion, and resource-close checks; test readers through production orchestration.

Migration risk and uncertainty

High scientific migration risk: preserve genotype order, physical indices, MAF>0 exclusion, common counts, window semantics, precision, and per-process cache lifetime. Do not replace streaming with dense matrices. Narrow the BIM-only broad exception fallback only after defining its valid use.

Existing design constraints

Aligns with docs/current/architecture.md “Shared normalization” and “Compute kernel,” docs/current/config-design.md “Workflow-Specific SNP Controls,” and docs/current/path-specification.md “LD score calculation.” The external raw-R² correction contract is documented; changing it would require a scientific contract decision.

StrongA3

Keep numerical error policy local

Confirmed notebook-composition defect: importing one workflow changes another calculation’s behavior.

Observed friction and affected paths

  • src/ldsc/_kernel/regression.py:19 and src/ldsc/_kernel/_jackknife.py:20 call np.seterr(divide="raise", invalid="raise") at import. src/ldsc/_kernel/sumstats_munger.py:71 sets invalid to ignore.
  • A fresh process starts with divide/invalid=warn. from ldsc import RegressionRunner changes them to divide=raise, invalid=ignore. Plain import ldsc alone did not trigger this state change.
  • src/ldsc/quantile_h2.py:226 eagerly evaluates contrast / contrast_se within np.where. Identical delete estimates return NaN enrichment p-values before the public regression import and raise FloatingPointError after it. The same input arrays were used in both calls.

Proposed change and tentative seam

Scope intended error behavior with local numerical contexts at the relevant operations, and use masked division for deliberately undefined zero-SE summaries. Leave the caller’s NumPy settings unchanged on success and failure.

Expected leverage, locality, and testing benefit

Leverage: users can combine workflows in notebooks without remembering import order. Locality: an estimator owns its own exceptional arithmetic. Testing: numerical behavior becomes repeatable independently of test collection order.

Deletion test

Ambient import mutation can be deleted without spreading useful orchestration. Necessary numerical exception semantics should reappear only at calculations that actually require them.

Tests that should survive or be added

Add fresh-subprocess public-import isolation, restoration after exceptions, and a hand-worked identical-delete/zero-SE quantile case. Retain IRWLS, jackknife, h2, rg, and quantile reference tests.

Migration risk and uncertainty

Do not simply remove all seterr calls: legacy code catches FloatingPointError in places. Preserve those intended local failure modes and avoid suppressing real numerical errors.

Existing design constraints

Supports the self-sufficient scientific Python interface and existing numerical invariants. No dedicated ADR requiring process-wide NumPy mutation was found.

StrongA5

Two real execution paths coordinate the same query eligibility and finalization rules across mutually dependent modules.

Observed friction and affected paths

  • src/ldsc/gene_ldscore_index.py:1867 derives indexed query statuses; src/ldsc/gene_ldscore_index.py:2027 constructs LDScoreCalculator() just to call its private _finalize_query_statuses method.

Proposed change and tentative seam

Deepen an internal query-finalization module used by both live and indexed assembly. Keep shared rules for query status, protected control behavior, column pruning, and result alignment behind it. Feed it the actual support/variance evidence from each path. Keep catalog resolution and gene-index publication where they belong.

Expected leverage, locality, and testing benefit

Leverage: both execution paths get the same query policy. Locality: changing skip/control rules no longer crosses workflow internals. Testing: identical evidence can be run through one finalization seam, then live/index round trips can verify integration.

Deletion test

Tests that should survive or be added

Migration risk and uncertainty

Existing design constraints

docs/current/gene-list-input-format.md, gene-list-diagnostics-and-repair.md, and gene-ldscore-index.md require consistent policy. The immutable index transaction and its digests are deliberate and remain unchanged.

StrongA6

Have fit outcomes own the fitted SNP population and diagnostics

Metadata independently recomputes the selection used by estimation.

Observed friction and affected paths

  • src/ldsc/regression_runner.py:714 applies the h2 chi-square filter; src/ldsc/regression_runner.py:2477 — _effective_regression_filter explicitly mirrors it for reporting. rg similarly duplicates filtering in _fit_rg_dataset (line 967) and _effective_rg_filter (line 2494).
  • Partitioned/rg family callers coordinate fitting and later filter reconstruction; h2 CLI does so at src/ldsc/regression_runner.py:2653. The kernel Hsq object receives a dynamic workflow attribute ld_score_regression_bins at line 762, later read by the writer path.

Proposed change and tentative seam

Create an internal workflow fit outcome carrying the estimator plus realized SNP/annotation selection, block count, and diagnostic bins. Capture these facts while assembling the actual fit arrays once. Preserve the current public estimator return contract unless a separate decision changes it.

Expected leverage, locality, and testing benefit

Leverage: reporting consumes fitted facts. Locality: filter changes occur once. Testing: compare saved n_snps and bins against the actual retained arrays, rather than testing two matching formulas separately.

Deletion test

Delete the mirrored filter helpers after callers use the fit outcome. Keep distinct h2 and rg scientific filtering rules inside their appropriate fit implementations.

Tests that should survive or be added

Retain numerical fits, two-step estimation, constrained intercepts, variable sample sizes, and diagnostics tests. Add small real-fit checks tying bins and metadata to the exact post-filter population.

Migration risk and uncertainty

Preserve h2’s multi-annotation default cap and rg’s explicit product filter. An internal result wrapper must not silently change public RegressionRunner return types.

Existing design constraints

docs/current/regression-configuration.md and the 2026-09-07 plotting specification require exact fitted-population diagnostics. This proposal strengthens that contract.

Proposed change and tentative seam

Expected leverage, locality, and testing benefit

StrongA8

Make failure-marker scope follow actual invocation semantics

A successful help request currently writes a false RUN_FAILED marker.

Observed friction and affected paths

  • src/ldsc/cli.py:251 wraps raw argv dispatch in a failure-marker context before parsing. src/ldsc/_logging.py:204 catches BaseException, including successful SystemExit(0).
  • Reproduced run_cli(["h2", "--output-dir", TMP, "--overwrite", "--help"]): return code 0, output directory created, RUN_FAILED.txt written with “Error: SystemExit: 0”. No materializing workflow ran.
  • src/ldsc/cli.py:285 independently resolves derived destinations and chromosome marker names from raw tokens; workflow decorators resolve those scopes again at src/ldsc/_logging.py:255. This duplication needs to remain narrowly scoped because parse failures are deliberately covered.

Proposed change and tentative seam

Use one small invocation-scope description for marker eligibility, destination, and chromosome scope. Explicitly distinguish successful parser exits from failed authorized attempts. Retain marker coverage for relevant parse/validation failures and the existing Python entry points.

Expected leverage, locality, and testing benefit

Leverage: help and inspection remain side-effect free. Locality: one place defines what constitutes a failed materializing invocation. Testing: the same invocation cases exercise CLI and Python lifecycle behavior.

Deletion test

Removing all CLI markers would discard required failure visibility. Remove duplicated semantic decisions and the misclassification of help; do not build a general workflow engine.

Tests that should survive or be added

Add overwrite+help, parser failure, repeated/equals-style options, successful retry, no-overwrite, nested destinations, and chromosome-scope cases. Retain the existing failure matrix.

Migration risk and uncertainty

Markers must still never roll back scientific files, block retries, or enter scientific metadata. Preserve command action ordering and parse-failure coverage required by the current design.

Existing design constraints

The 2026-09-07 plotting specification and docs/current/workflow-logging.md “Failed Overwrite Markers” concern failed attempts. A successful help exit is not such an attempt.

def bundle_for(metadata):
    return AnnotationBundle(
        metadata=metadata,
        baseline_annotations=pd.DataFrame({'base': np.ones(len(metadata))}),
        query_annotations=pd.DataFrame(index=metadata.index),
        baseline_columns=['base'], query_columns=[], chromosomes=['1'], source_summary={},

def probe_plink():
    prefix = ROOT / 'tests/fixtures/plink/plink'
    metadata = pd.read_csv(prefix.with_suffix('.bim'), sep=r'\s+', header=None,
                           names=['CHR', 'SNP', 'CM', 'POS', 'A1', 'A2'])
    gc = GlobalConfig(snp_identifier='rsid')
    panel = PlinkRefPanel(gc, RefPanelConfig(backend='plink', plink_prefix=str(prefix)))
    config = LDScoreConfig(ld_wind_snps=10, ld_wind_cm=None, ld_wind_kb=None,
                          whole_chromosome_ok=True, snp_batch_size=3)
    with mock.patch.object(kernel, 'PlinkBEDFile', wraps=kernel.PlinkBEDFile) as reader:

        print({'probe': 'PLINK initialization', 'reader_constructions': reader.call_count,
               'retained_rows': len(result.baseline_table), 'source_rows': len(metadata)})
